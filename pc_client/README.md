# Windows 直流电源客户端

下载并双击 EXE 启动。USB 串口号由 Windows 分配，下文用 COM4 代表后板 CH340E 数据口，用 COM3 代表 ESP32 烧录和维护口。 [Windows 便携版](https://github.com/chuckie0329/power_module/releases)

## 连接和控制

1. 在顶部选择 **USB 有线** 和 **COM4**，点击 **连接**。客户端先尝试 921600 波特，连接旧固件时可回退到 115200。状态同步后即可操作主输出和两路继电器。
2. 在 **输出设定** 中填写电压和限流，点击 **应用设定** 写入。使用 ESP32 固件 v1.1.3 时，成功应用设定会保持主输出原来的开关状态。若触发 SX150C 保护，客户端会显示关断和保护状态。主输出按钮随设备读回在 **开启输出** 和 **关闭输出** 之间切换。**K1**、**K2** 分别切换对应继电器。
3. 选中 **M0～M10** 中的目标并点击 **切换数据组**。切换时关闭主输出，切换后显示目标组的设定值和保护阈值。目标组的 **M-OUT** 须为关闭，才能从客户端调出。
4. 主输出关闭时，在当前组的 **保护阈值** 中编辑 OVP、OCP 或 OPP，点击 **应用 OVP/OCP** 或 **应用 OPP**。OPP 步进为 0.1 W。固件 v1.1.3 的 OPP 范围为 **0.1～100.0 W**，v1.1.1 和 v1.1.2 的上限为 75.0 W。下方显示设备的实际读回值，包括预设组出厂的 160.0 W。如果设备显示 **校对 OCP**，输入 SX150C 面板当前组的过流保护读数以确认寄存器单位。
5. 固件 v1.2.1 起，点击 **断开**、退出客户端或意外掉线时，主输出和两路继电器保持原状态。重连后，客户端显示设备当前状态。

在数据组下拉框选中一组，点击 **名称和备注** 即可编辑。自定义名称显示在原组号旁边，选中的组下方会显示备注。鼠标停在组名或备注上可查看全文。两个字段都留空并保存可清除该组的信息。名称和备注按设备 ID 保存在当前 Windows 用户的客户端设置中，同一设备通过 USB 或蓝牙重连时共用。

使用 v1.1.5 及以上固件时，首次在 Windows 蓝牙设置中添加 `PM-xxxx`，输入固定 PIN **112233**。配对后，在客户端选择 **蓝牙 BLE**，扫描并连接设备。Windows 会保存配对记录供下次连接使用。 [蓝牙配对与恢复](../BLE-PAIRING-RECOVERY-TEST.md) · [ESP32 固件说明](../firmware/README.md)

## 悬浮模式

点击主界面顶部的「悬浮」进入半透明、置顶的小窗口。主窗口从任务栏收起，系统托盘显示电源图标。小窗口只显示实时输出电压、电流和功率，以及主输出和 K1、K2 开关；未读到有效数据时用「—」表示。开关显示的是确认或读回的状态，K1/K2 对应线圈命令而非物理触点反馈。拖动读数区域可移动窗口，双击读数区域或点击托盘图标可恢复主窗口。

切换模式不会断开连接、改变采样配置或发送输出命令。悬浮模式不会使用主窗口中尚未应用的电压和限流设定来开启输出：请先回主窗口处理设定。固件 v1.2.1 起，断开连接不等于关断输出。

## 升级客户端或固件

主窗口的「升级」同时显示 Windows 客户端和 ESP32 固件版本。**v1.0.0 不支持自动替换客户端**，首次请从 [PC v1.0.1 发布页](https://github.com/chuckie0329/power_module/releases/tag/pc-v1.0.1) 下载 EXE，关闭旧程序后手动运行新版。

- **Windows 客户端**：v1.0.1 起，点击客户端一栏的「升级」下载并校验新版。若原先已连接，旧客户端先正常断开；新版按相同 USB 串口或 BLE 地址重连并核对同一设备身份。新版启动并确认原连接后才尝试移除旧 EXE。切换失败时保留旧 EXE。较早且断开会影响输出的固件须先确认输出与继电器均已关闭。
- **ESP32 固件**：新版固件验证通过后下载到 EXE 同目录的 `PowerModule-ESP32.bin`；本地已有经过同样校验的最新镜像时会直接复用，也可手动选择本地 BIN。下载不会自动刷写。连接支持升级的设备，并关闭主输出和两路继电器后，在固件行点击「升级」并确认。设备会重启并重新连接，请保持供电和连接。

PC 自动切换需要 Windows 正式 EXE 及可写的客户端目录；源码模式仍支持手动选择固件。

[firmware-bin]: https://github.com/chuckie0329/power_module/releases/download/v1.2.1/PowerModule-ESP32.bin
[firmware-hex]: https://github.com/chuckie0329/power_module/releases/download/v1.2.1/PowerModule-ESP32.hex

2026-11-21 在实机上用同一份 660944 字节的 v1.2.0 镜像验证升级。COM4 从 app0 切换到 app1，含重启和确认用时 60.9 秒。BLE 从 app1 切换到 app0，用时 141.7 秒。中途取消、校验失败和 BLE 断开均保留了原启动分区。另一次启动到 app1 后省略客户端确认，设备约两分钟后自动回到 app0，主输出读回关闭。

v1.2.1 已通过 COM4 升级并确认启动，实机在输出关闭时验证了断开重连和设定读回。模拟测试覆盖主输出与两路继电器开启时的连接中断，以及重连后的显式关断。

## 输出曲线和统计

输出开启后，客户端记录 SX150C 的电压、电流和功率。横轴左端从确认开启时的首个有效读数开始，曲线向右增长，达到设定时长后滚动显示最近的数据。可以同屏查看三条曲线，也可以单独查看其中一条。点击 **独立窗口** 可放大查看，在 **最近** 数字框中输入 1～120 分钟。

PC 客户端默认采样频率为 **20 Hz**，连接后自动设置。链路支持的最高频率低于 20 Hz 时，客户端选择该链路的最高档位。固件 v1.1.7 起，SX150C 使用 115200 波特时，有线可选 **0.5、1、2、5、10、20 或 30 Hz**。固件 v1.1.8 起，BLE 协商的 ATT MTU 达 247 时也可选 **30 Hz**。MTU 为 100～246 时最高 5 Hz，低于 100 时使用 0.4 Hz。曲线下方的「实际 Hz」按最近 5 秒的有效新样本统计。

关闭主输出后，曲线停在最后一次有效读数，保留当前显示范围内的图像和平均功率。确认主输出再次开启时，主界面和独立窗口清空上一轮曲线和统计值，从左端开始记录新一轮。暂停期间仍可调整查看范围或保存本轮数据。

切换数据组、掉线和超时也会断开曲线。平均功率按选定范围内的有效样本间隔加权，有效时长同时显示在平均值旁。每轮输出记录在客户端中最多保留最近两小时，长时间范围的曲线按屏幕像素保留峰谷绘制。

点击 **保存数据** 可导出当前保留的全部原始样本为 CSV，包含本地时间、电压、电流、功率和曲线段。关闭输出后仍可保存。

对于 `MODEL=4008`、`VERSION=100`，客户端将 `IOUT` 和 `POWER` 按 1 mA 和 10 mW 每计数换算。实时仪表、曲线和平均功率均使用同一套换算。

## 固件

直接控制、采样频率设置和 M0～M10 切换自 ESP32 固件 **v1.1.0** 起支持。**v1.1.1** 增加 OPP 写入与核对读回，**v1.1.2** 增加有线 10 Hz 和 20 Hz 采样档，**v1.1.3** 支持运行中调整电压和限流，并将 OPP 上限提高到 100 W。**v1.1.4** 配置固定 PIN 蓝牙配对，**v1.1.5** 修复 BLE 控制服务的注册，**v1.1.6** 增加蓝牙高速采样档。**v1.1.7** 将 CH340E 有线波特率提高到 921600，增加有线 30 Hz 档，常规推送等待新的 SX150C 读数。**v1.1.8** 增加蓝牙 30 Hz 档，客户端连接后根据设备上报的档位显示。**v1.2.0** 增加 COM4 和 BLE 应用固件升级。新版 Windows 客户端的 OCP 输入修复也适用于 v1.1.2。 [最新烧录镜像][firmware-hex] · [烧录说明](../firmware/README.md)

v1.0.2 曾通过 COM4 实机验证 M0 的 OVP/OCP 写入与读回。2026-11-19 在 v1.1.0 实机上用新版客户端连接 COM4，直接写入并读回 11.99 V，再恢复至 12.00 V。M0～M10 均调出并读回成功，主输出全程关闭。关闭并重开客户端后，M1 的测试名称和备注均成功读回。

v1.1.0 联调时，实机 M1～M10 的 OPP 均读回 160 W。2026-11-19 烧录 v1.1.1 后，用新版客户端经 COM4 将 M1 的 OPP 从 160.0 W 写为 75.0 W，读回 75.0 W。此时「开启输出」按钮可用，主输出保持关闭。

2026-11-19 烧录 v1.1.2 后，经 COM4 实测两档采样。10 Hz 档在有效 25.8 秒内记录 259 个样本，约 10.0 Hz。20 Hz 档在有效 29.1 秒内记录 585 个样本，约 20.1 Hz。关断再开启输出后，电压曲线正确分段，段间留空。两段从 0 V 上升到 5 V 后的渐变填充均正常。测试结束后恢复原数据组和设定，主输出关闭。

2026-11-20 使用 v1.1.6 经 Windows BLE 实测，ATT MTU 为 247，SX150C 串口为 115200 波特。主输出关闭时，5 Hz 和 10 Hz 档的新样本频率分别为 5.00 Hz 和 10.00 Hz。20 Hz 档连续推送约 30 秒，收到 600 帧及 566 个新样本，实际为 18.86 Hz。另一轮穿插 5 次状态查询，实测 18.76 Hz，查询均成功，最长耗时 110 ms。

2026-11-21 使用 v1.1.7，经 COM4 在 921600 波特下实测有线 30 Hz。SX150C 为 115200 波特，主输出关闭。60 秒内收到 1800 个不同采样时间戳，重复和无效帧均为零。每 5 秒收到 149～151 个新样本。测试中 11 次状态查询全部成功，最长耗时 63 ms。

同版固件经 Windows BLE 实测，ATT MTU 为 247，主输出关闭。20 Hz 档在 30 秒内收到 600 个不同采样时间戳，重复和无效帧均为零，期间 5 次状态查询全部成功。

2026-11-21 使用 v1.1.8，经 Windows BLE 实测 30 Hz 档。ATT MTU 为 247，SX150C 为 115200 波特，主输出关闭。连续采样 60 秒，客户端收到 1800 个新读数，平均 30.00 Hz，最长接收间隔 79 ms。每 5 秒执行一次状态查询时，另一轮 60 秒收到 1782 个完整状态推送，其中 1777 个进入客户端采样统计，平均 29.62 Hz，最长接收间隔 187 ms。11 次查询全部成功，最长耗时 94 ms。两轮均无重复采样或无效帧，完成后恢复测试前的 2 Hz。

## 从源码运行

在项目根目录使用 Windows x64 Python 3.12。

```powershell
python -m pip install -r pc_client/requirements.txt
python -m pc_client
```

便携版使用 PyInstaller 6.16.0 打包。 [Qt for Python 打包文档](https://doc.qt.io/qtforpython-6/deployment/deployment-pyinstaller.html) · [PyInstaller 命令](https://pyinstaller.org/en/v6.16.0/usage.html)

```powershell
python -m pip install pyinstaller==6.16.0
.\tools\build_pc_windows.ps1
```
